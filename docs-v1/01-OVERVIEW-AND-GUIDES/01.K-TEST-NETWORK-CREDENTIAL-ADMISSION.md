# 101: Test Network credential admission

Use this path only for a real registration into an isolated Test Network host.
It is not production-network adhesion and cannot select production policy.

1. A portal creates the controller wallet before application and commits the
   actor-signing JWK thumbprint.
2. Postal-address verification is not part of Test Network admission and the
   `OrganizationTestNetworkCredential` contains no postal state or code binding.
3. A human issuer employee signs that admission VC plus the normal
   Organization, LegalRepresentative and ServiceController VCs. The latter
   three carry `TestNetworkCredential` and individual ML-DSA-65 assertion
   proofs.
4. `Organization/_transaction` carries the admission VC in
   `resource.organizationTestNetworkCredential` and the three domain VCs in
   `resource.testNetworkCredentials`, with `verification.resourceType=contract`
   on the `test-network` route. There is no authorization-named alias.
5. GW verifies issuer, signer policy, every proof, expiry, PDF evidence, organization DID and
   identifier and controller email/key commitment. Failure is
   terminal; it does not fall back to ICA.
6. GW returns the three domain VCs in `vc[]` and the canonical Offer id.
7. `Order/_batch` issues the host-owned controller activation credential; the
   portal reads it from the Order response instead of supplying a client value.
8. `Token/_exchange` consumes that credential and DCR binds purpose-separated device
   keys to the original controller actor. Only then is the tenant active.

Canonical signer authorization uses live issuer/controller DID documents.
During the publication gap, `HOST_ORGANIZATION_AUTHORIZATION_SIGNERS` is a
revocable registry of exact issuer DID, employee DID (including its stable
email-hash member id), `RESPRSN` role, status and ML-DSA-65 JWK thumbprint. A
first unpublished key may instead require the portal/host HMAC attestation,
created only after the BFF unlocks the existing reviewer wallet. It supplements
but never replaces the ML-DSA-65 proof. Fabric can later own the employee,
role, key and revocation policy. Remove the bridge when DID publication is live.
It cannot run on `network`; production remains ICA-backed.

Audit evidence must show redacted VC/Offer/job/DCR identifiers and final host
readback. Never log the activation credential, ID token, PIN, seed, recovery share
or private JWK members.

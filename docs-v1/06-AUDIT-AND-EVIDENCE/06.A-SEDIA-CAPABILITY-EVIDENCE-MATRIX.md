# SEDIA Capability Evidence Matrix

Status: Closed implementation evidence

Purpose: record the implemented project boundary and point evaluators to its
reproducible evidence. SDK API-shape details remain in their owning SDK
repositories and are not project acceptance gaps.

## Implemented responsibility map

| SEDIA capability | Implemented owner | Closure evidence |
| --- | --- | --- |
| Participant organization and legal-representative verification | Dataspace ICA | Signed verification result, organization/legal-representative/controller credentials, governed status records and negative verification tests |
| Controller publication of products and services | the external portal/BFF using Pontus-X | Versioned portal/BFF publication evidence and the externally resolvable Pontus-X catalogue entry; Pontus-X is not reproduced by the local host package |
| Host and tenant technical discovery | GW CORE and dataspace ICA | Resolvable DID documents, `/.well-known/dspace-version`, DSP/DCAT endpoints and provider-discovery responses |
| Authenticated participant node | GW CORE | Tenant-isolated asynchronous APIs, DIDComm/FAPI identity checks, protected persistence and positive/negative endpoint tests |
| Subject-controlled secondary use | GW CORE through the typed Node SDK | Reversible FHIR Consent decision; enabling anonymization allows the governed projection to be refreshed and disabling it stops subsequent synchronization while preserving the already anonymized evidence. Private search fields remain on the same projected resource record, not a separate collection |
| Digital-twin discovery and governed access | GW CORE | Authenticated FHIR search over digital-twin resources, SMART authorization and same-tenant/bilateral inter-tenant access evidence |
| Permissioned state and audit traceability | Hyperledger Fabric adapters and deployed peer/channel/chaincode topology | Transaction submission, ledger readback and correlated evidence records for the operations claimed by the deliverable |
| Local reproducibility | Versioned GW CORE/ICA/Fabric host package | Digest-pinned images, deterministic configuration, automated tests and generated hash manifest described by the reproducible-host deliverable |

## Demonstrated local closure flow

1. Start the digest-pinned local participant environment.
2. Verify the organization, its legal representative and its controller through
   dataspace ICA.
3. Activate the tenant and resolve its technical DID/service endpoints.
4. Ingest the governed FHIR/IPS data through the authenticated GW route.
5. Toggle the subject's anonymization decision and verify that synchronization
   starts or stops accordingly.
6. Execute an authorized positive digital-twin search and its corresponding
   negative authorization case.
7. Verify the permissioned-ledger transaction/readback evidence claimed by the
   run.
8. Generate the evidence manifest containing artifact digests and test results.

## Scope boundary

The SEDIA closure evidence does not redefine SDK method names. The portal/BFF
integration table owns those mappings. This matrix contains only the approved
project capabilities and their reproducible evidence.

Pontus-X and Fabric remain complementary: Pontus-X is the external federated
catalogue used by the controller-facing portal/BFF; Fabric is the permissioned
state and evidence layer used by the participant runtime.

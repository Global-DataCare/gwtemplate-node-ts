# Implemented compliance credential endpoint

This page records only the compliance-credential surface implemented by GW
CORE. It does not describe an external clearing-house deployment or claim that
GW CORE implements a complete external compliance platform.

## Implemented endpoint

```http
POST /{tenantId}/cds-{jurisdiction}/v1/{sector}/identity/oidc/credential
Authorization: Bearer <access-token>
Content-Type: application/json
```

The route:

- resolves an existing tenant and its DID document;
- builds a legal-participant credential from that tenant's stored claims;
- signs one `JsonWebSignature2020` proof with the host credential-signing key;
- uses `ML-DSA-44` by default, or the configured legacy signing algorithm when
  present;
- accepts `?pqc=true` or `X-PQC-Signature: true` to select `ML-DSA-44`.

In strict security mode, the bearer is verified by the configured application
authorization manager. Demo-compatible modes may allow the explicitly enabled
insecure bearer path.

## Published metadata

GW CORE publishes tenant-scoped OpenID and credential-issuer metadata through
the corresponding `/.well-known` routes. Those discovery documents describe
the local GW endpoints; they are not evidence that an external compliance
provider is deployed locally.

## Boundary

This credential is compliance evidence. It is not a login token, a SMART access
token, a Fabric enrollment certificate, or an ICA onboarding credential.

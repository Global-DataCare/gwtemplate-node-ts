# Publish products and services to your tenant catalogue

Call the publishing function in the portal backend after the organization
controller approves the listing. Use the signed-in controller's existing
gateway client and the tenant selected in that session. Keep the same entry ID
when updating a listing. Send products and services in separate batches.

## Publish or update a listing

Copy this function into the portal backend. Use the existing secure
`HttpRuntimeClient` for the tenant. Take `tenant` from its route, and
`controller.did` and `controller.clientId` from the registered session.
Persist `operationId` with the change so retries use the same value.

```ts
import type { HttpRuntimeClient } from 'gdc-sdk-node-ts'

type Offering = {
  type: 'Product' | 'Service'
  id: string
  attributes: Record<string, unknown>
}

export async function publishTenantOfferings(
  client: HttpRuntimeClient,
  tenant: { id: string; jurisdiction: string; sector: string; did: string },
  controller: { did: string; clientId: string },
  entries: readonly Offering[],
  operationId: string,
) {
  const route = [tenant.id, `cds-${tenant.jurisdiction}`, 'v1', tenant.sector]
    .map(encodeURIComponent).join('/')
  const path = `/${route}/organization/org.schema/Catalog/_upsert`
  const { poll } = await client.submitAndPoll(path, `${path}-response`, {
    thid: operationId,
    iss: controller.did,
    aud: tenant.did,
    client_id: controller.clientId,
    type: 'application/didcomm-plain+json',
    body: { jsonapi: { version: '1.1' }, data: entries },
  })
  const receipt = poll.body as { thid?: string; body?: { total?: number } }
  if (!entries.length || receipt.thid !== operationId || receipt.body?.total !== entries.length) {
    throw new Error('The gateway did not confirm the complete catalogue update.')
  }
  return { published: receipt.body.total }
}
```

Include the reviewed listing's `name`, `description`, `category` and
`offers` in `attributes`. Use `offers: []` when the listing has no commercial
offer. Use the public listing's existing URL and commercial terms where
applicable. The gateway sets the publisher from the tenant.

## Verify the result

1. Open the tenant's public `/dsp/catalog/dcat.json` under its tenant base URL.
2. Follow the offering catalogue link in `dcat:service` to
   `/dsp/catalog/offerings.json`. Find the listing by its `type` and `id`,
   and compare the updated fields before reporting success in the portal.
3. Confirm the host catalogue lists that tenant catalogue in `dcat:catalog`.

A commercial listing update changes the public listing feed referenced from
DCAT. A signed Gaia-X service offering has its own issuance and terms.
An external dataset and its access services require their own publication
contract for `Dataset` and `DataService`.

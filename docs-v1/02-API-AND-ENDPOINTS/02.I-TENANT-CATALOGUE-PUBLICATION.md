# Publish products and services to your tenant catalogue

Call the publishing function in the Global Data Care portal backend after the
organization controller approves the listing. The controller must already
have a registered profile for the destination tenant.

## Install the portal dependencies

```bash
npm install --save-exact gdc-sdk-node-ts@2.9.33 gdc-common-utils-ts@2.9.33
```

Reuse the BFF's configured `ServerProfileSessionManager`. Its constructor takes
the existing profile store, profile sealer, gateway origin, recipient-DID key
resolver and app identity. Follow the
[registered controller example](https://github.com/Global-DataCare/gdc-sdk-node-ts/blob/main/docs/101-SDK_END_TO_END.md)
to set up that manager.

## Reopen the controller and publish or update a listing

```ts
import type { ServerProfileSessionManager } from 'gdc-sdk-node-ts'
import { buildCataloguePrimaryDocument } from 'gdc-common-utils-ts/convert/ocean-catalogue'

type ControllerSession = Parameters<ServerProfileSessionManager['openOrganizationController']>[0]
type CatalogueEntry = Parameters<typeof buildCataloguePrimaryDocument>[0][number]
type Offering = CatalogueEntry & { type: 'Product' | 'Service' }

export async function publishTenantOfferings(
  profileSessions: ServerProfileSessionManager,
  controllerSession: ControllerSession,
  reviewedEntries: readonly Offering[],
  operationId: string,
) {
  const document = buildCataloguePrimaryDocument(reviewedEntries)
  const { profile, sdk } = await profileSessions.openOrganizationController(controllerSession)
  const { tenantId, jurisdiction, sector } = profile.routeContext
  const route = [tenantId, `cds-${jurisdiction}`, 'v1', sector].map(encodeURIComponent).join('/')
  const path = `/${route}/organization/org.schema/Catalog/_upsert`

  const { poll } = await sdk.submitAndPoll(path, `${path}-response`, {
    thid: operationId,
    iss: profile.actorDid,
    aud: profile.providerDid,
    client_id: profile.clientId,
    type: 'application/didcomm-plain+json',
    body: document,
  })

  const receipt = poll.body as { type?: string; thid?: string; body?: { total?: number } }
  if (receipt?.type !== 'org.schema.catalog-publication' ||
      receipt.thid !== operationId || receipt.body?.total !== document.data.length) {
    throw new Error('The gateway did not confirm the complete catalogue update.')
  }
  return { published: receipt.body.total }
}
```

- `controllerSession.ownerId` and `idToken` come from the authenticated BFF
  session. `profileId` identifies the registered controller selected by that
  account. Pass either `pin` through the existing unlock flow or
  `authorizedWalletSeed` from the BFF's protected custody.
- The SDK restores the registered keys and signs and encrypts the request.
  The sender DID, recipient DID, client ID and tenant route come from the
  profile that the SDK opened.
- `reviewedEntries` contains the approved public product or service resources.
  Each has a stable ID and Schema.org attributes such as `name`, `description`,
  `category` and `offers`. Use `offers: []` for a listing without a commercial
  offer. Keep products and services in separate batches. The gateway sets
  the publisher from the tenant.
- `operationId` is the identifier the BFF stored for this approved change.
  On retry, reuse it and the same listing IDs.

## Verify the result

1. Open the tenant's public `/dsp/catalog/dcat.json` under its tenant base URL.
2. Follow the offering catalogue link in `dcat:service` to
   `/dsp/catalog/offerings.json`. Find the listing by its `type` and `id`,
   and compare the updated fields before reporting success in the portal.
3. Confirm the host catalogue lists that tenant catalogue in `dcat:catalog`.

A commercial listing update changes the public listing feed referenced from
DCAT. A signed Gaia-X service offering has its own issuance and terms.
An external dataset and its access services require their own publication
contract for `Dataset` and `DataService`.


## Prepare datasets already published in Pontus-X

Run the conversion in the portal backend with the resolved Ocean DDOs for
the organization. The optional `landingPage` is the public asset page the
portal already knows.

```ts
import {
  buildCataloguePrimaryDocument,
  projectOceanDatasetEntries,
} from 'gdc-common-utils-ts/convert/ocean-catalogue'

export function preparePontusDatasets(
  sources: readonly { ddo: unknown; landingPage?: string }[],
) {
  return buildCataloguePrimaryDocument(sources.flatMap(projectOceanDatasetEntries))
}
```

The resulting JSON:API document preserves the external DID and includes each
`Dataset` and its linked `DataService` entries. Publication of those resources
requires the external dataset contract and a verified readback from the target
tenant. The `Catalog/_upsert` example above implements the product and service
contract.

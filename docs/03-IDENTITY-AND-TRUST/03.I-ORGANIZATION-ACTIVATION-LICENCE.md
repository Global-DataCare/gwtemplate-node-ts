# Organization controller activation licence

## Current GW contract

The controller registration sequence is:

`Order → activation licence → Token/_exchange → Device/_dcr`

`Order` reserves/issues a device-licence seat and returns its opaque activation
code in `org.schema.IndividualProduct.serialNumber`. The code is not a portal
login OTP, PDF confirmation code, postal-provider code or verifiable credential.

`Token/_exchange` resolves the protected licence by the activation-code index,
checks its licensed verified email or telephone, checks the annual licence
expiry, and changes an issued seat to active. DCR then binds the registered
client installation. The first organization-controller enrollment uses this
code once in its transaction flow; the existing GW multi-device policy may
reuse an active seat only for the same authenticated actor and within its
configured device allowance.

GW licences are currently created with a one-year `exp`. Therefore an unused
activation code remains governed by annual licence expiry; there is no separate
ten-minute activation-code TTL. Expired licences fail exchange. Login/mailbox
OTPs remain separate short-lived authentication challenges.

## Delivery and renewal target

Portals own the delivery channel, never the activation value:

- Test Network email delivery occurs only after review and GW licence issue.
- The production postal delivery occurs only after legal, professional and address
  verification.
- The clear code must not be logged or stored in a portal database; GW retains
  its protected lookup and licence state.
- The organization should be notified by email one month before expiry. A
  governed renewal may require a new postal address verification and a renewed
  annual licence/code before the old licence expires.

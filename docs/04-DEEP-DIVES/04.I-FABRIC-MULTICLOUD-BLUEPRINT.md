## Why this moved

`gwtemplate-node-ts` consumes Fabric. It is not the owner of:

- `fabric-ca-root` / `fabric-ca-ica`
- configtx/channel bootstrap
- Kubernetes manifests for Fabric
- local Fabric devnet lifecycle
- multi-ICA PKI layout

Those assets now live in `fabric-multicloud/` beside this repo.

## What remains relevant from GW

GW still owns:

- Fabric gateway client usage
- connection profile consumption
- runtime identities provided through env vars
- application logic and tests that exercise the ledger

The recommended local dev path is:

1. bootstrap Fabric in `../fabric-multicloud/devnet/fabric-v3`
2. generate `.env.fabric-devnet`
3. run GW tests or local backend using that env file

## Temporary compatibility layer

Some PKI helper entrypoints still live in this repo because the current GW
runtime and demo bootstrap paths still import them directly:

- `scripts/generate-root-ca.ts`
- `scripts/generate-ica.ts`
- `scripts/generate-pki-chain.ts`
- `src/utils/pki-chain.ts`

They already write CA state into the sibling `../fabric-multicloud` folder and
should be treated as compatibility shims, not as long-term ownership of Fabric
infrastructure by `gwtemplate-node-ts`.

## Initial logical ICA domains

At the infra layer, the first domains to keep ready are:

- `health-care-eu`
- `animal-pet-eu`
- `animal-pet-na`

Detailed business taxonomy beyond that should be documented in the appropriate
domain repos, not here.

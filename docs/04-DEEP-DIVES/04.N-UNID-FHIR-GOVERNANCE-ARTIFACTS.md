# UNID-governed FHIR and ODRL artifacts

Fundación UNID controls the stable FHIR canonical authority:

```text
https://unid.online/standards/fhir
```

The canonical URL identifies an artifact across releases. Its FHIR `version`
identifies the semantic release, and the matching immutable Git tag in
`Fundacion-UNID/fabric-multicloud` is the auditable source. The publication
service may redirect or proxy the stable canonical URL to that tagged source
while preserving the canonical URL embedded in the resource.

This URL is a standards namespace, not a tenant FHIR server. It contains no
personal or organization records. Each tenant exposes its own `/fhir/metadata`
and data endpoints under its operational URL.

GW reads:

```env
FHIR_GOVERNANCE_CANONICAL_BASE_URL=https://unid.online/standards/fhir
FHIR_GOVERNANCE_IMPLEMENTATION_VERSION=1.0.0
FHIR_ENABLE_CONTRACT_SEARCH_PARAMETERS=false
```

The centrally published `CapabilityStatement/gw-core` uses `kind=capability`.
Each tenant metadata response uses `kind=instance`, declares its own
`implementation.url` and references the central profile through
`instantiates`. The tenant statement advertises the custom Communication search
parameters that the runtime already supports and links their canonical
SearchParameter resources. Contract definitions, including `Contract.type`,
may be published before execution support exists, but they stay out of the
CapabilityStatement until `FHIR_ENABLE_CONTRACT_SEARCH_PARAMETERS=true` and
the corresponding search implementation has been validated.

Custom search codes follow exact FHIR API spelling: lowercase and hyphenated.
FHIR resources and SearchParameters name interoperable targets and indices;
ODRL remains the policy language persisted by the `antifraud-<region>` plane.

Policy routing is owner-based:

| Owner | Ledger plane |
| --- | --- |
| individual | `identity-global` |
| animal | `animal-pet-<region>` |
| organization | `antifraud-<region>` |

Care route sectors are a separate organization/service dimension:

| Provider sector | Ledger plane |
| --- | --- |
| human care | `health-care-<region>` |
| animal care | `animal-care-<region>` |

Existing sector-routed Consent assets require an explicit migration before
being moved. The taxonomy helper defines the clean contract for new policy
work without silently rewriting already deployed ledgers.

`antifraud` is an independent FHIR-capable business sector for Company Book,
Family Book and other non-health applications. Its contracts, invoices,
coverage/copay records and verification evidence may use FHIR resources, but
the sector itself is neither `health-*` nor `animal-*`.

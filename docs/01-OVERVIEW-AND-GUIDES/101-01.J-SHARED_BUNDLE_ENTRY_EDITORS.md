## GW Current Contract

With the shared package version currently installed by GW, the public typed
clinical entry editors available here are:

- `BundleEntryEditor.asVitalSign()`
- `BundleEntryEditor.asObservation()`

GW does not currently consume published typed entry editors here for:

- `asAllergy()`
- `asMedicationUseStatement()`
- `asMedicationStatement()`
- `asCondition()`

That is why GW tests can show direct chaining for vital signs, but still use
generic entry editing for allergies, medications, and conditions.

## What GW Should Teach

GW should teach consumption, not ownership.

For integrators and app developers:

- use the shared `ipsBundleReader` pattern for reading one IPS
- use shared section constants from `HealthcareBasicSections` /
  `HealthcareCoreSections`
- use shared fixtures/examples from `gdc-common-utils-ts`
- use `BundleEditor` and typed entry editors when they already exist
- use `setClaim(...)` / `getClaim(...)` only as fallback escape hatches

## Reader Vs Editor

Keep the mental model simple:

- `ipsBundleReader` reads
- `BundleEditor` edits/builds

After editing, recreate or refresh the reader from the updated bundle.

## Reader API To Use Today

The canonical high-level IPS reader API is documented upstream.

The important methods are:

- `ipsBundleReader.getSections()`
- `ipsBundleReader.getSectionSummary({ sections? })`
- `ipsBundleReader.getResources({ ... })`
- `ipsBundleReader.getAllergies({ ... })`
- `ipsBundleReader.getConditions({ ... })`
- `ipsBundleReader.getMedications({ ... })`
- `ipsBundleReader.getVitalSigns({ ... })`
- `ipsBundleReader.getLocalTextAndIntDisplay(resource)`
- `ipsBundleReader.getXhtmlOrDerived(resource)`
- `ipsBundleReader.getNarrative(resource)`

In code today that reader currently comes from:

```ts
import { createFhirDocumentFacade } from 'gdc-sdk-core-ts';

const ipsBundleReader = createFhirDocumentFacade(ipsInput);
```

## Section Selector Rule

The selector rule that GW should preserve is:

- `sections === undefined` means all sections
- `sections.length === 0` means all sections
- otherwise only the listed sections are included

That rule should stay identical in:

- generic resource queries
- date queries
- per-family clinical queries
- section summaries

## What Is Still Fallback Or TODO

Still fallback today in GW:

- generic `setClaim(...)`
- generic `getClaim(...)`

Still TODO upstream:

- full typed entry editors for allergies, medications, conditions, and the rest
  of the IPS families
- one complete high-level summary/query layer for all IPS families
- one section-specific markdown path per major IPS area
